# 上下文预算与自动压缩

当前版本：0.7.1。模型配置中的 `profile.context_window` 指定用户核实的上下文窗口，各供应商和模型需分别设置。未配置时使用 `guardrails.context_chars / 3` 的本地保守预算，默认 40000 token；UI 不将其冒充模型真实上限。

输出预留优先使用 API 的 max_completion_tokens / max_tokens，其次 profile.output_reserve，否则取窗口四分之一且最多 8192；另保留窗口 5%（至少 256）的余量。输入触发阈值取窗口 80%与“窗口减输出预留和余量”中的较小值，压缩目标为阈值的 80%。这不会自动改变供应商的生成参数。

请求前先估算消息与工具定义。过长工具结果保留首尾；压力仍大时，将已闭合的工具批次从旧到新转换成结构化摘要。摘要保存调用标识、参数摘录、状态、错误、恢复决定和结果；大量写入内容以长度和 SHA-256 表示。保留的批次维持原始 assistant/tool 对应关系，摘要不能授予权限。

压缩投影作为持久检查点复用；后续请求在检查点上追加新证据，只有再次达到压力阈值才重新压缩。配置、输入或历史来源变化时重新建立投影。当前目标和权限不裁剪；固定输入本身过大时明确要求缩小输入或调整正确的窗口。对话历史按消息边界摘录，完整原始记录仍保留在 SQLite。

输入区显示估算占用与已配置窗口，压缩详情默认折叠在执行详情。真实 usage 独立记录。估算采用 UTF-8 启发式和固定图片估算值，与供应商 tokenizer 有偏差。

这是**本地结构化/摘录压缩**，不额外调用模型，不是无损记忆，也不是 OpenAI Responses 原生 compaction。尚无手动 /compact、模型语义摘要或供应商溢出后的定向压缩重试。现有测试验证持久复用、协议配对、预算边界及压缩后不会重复写文件；真实模型的长任务记忆质量仍需评估。
