你是负责实现本项目的资深 Agent 工程师、全栈工程师和 Windows 桌面应用工程师。请在当前空工作区中，从零开发一个运行在 Windows 本地、通过可配置的大语言模型 API 执行任务的个人通用 Agent。

请实际编写、运行和验证代码，不要停留在架构建议、静态页面或功能占位。最终目标包括日常问答、联网研究、coding、本地文件与办公文档处理、网页操作、按需桌面软件操作、定时任务、长期记忆、MCP 和可选多模型协作。按下面的阶段实施，持续保留可运行版本。不要把“支持大多数任务”解释成可以保证操作所有软件或完成所有任务；能力、依赖和限制必须真实呈现。

一、用户已确定的产品需求

1. 本地优先，主要用于 Windows 电脑。模型推理由用户配置的外部 API 提供。用户暂时不会提供 API 密钥，你必须先做好真实接入接口、设置界面、确定性模拟服务和测试，之后用户自行配置 API。
2. 同时提供本地网页和独立桌面软件。参考 ChatGPT 的聊天与会话体验，以及 Codex 的工作区、任务、授权、文件变更和执行日志布局，但不复制品牌标识，也不声称这是官方产品。
3. 支持多个 API 配置和手动切换模型。另有默认关闭的多模型协作开关。开启后由主模型拆解任务、分派给适合该领域的模型，再整合和验证结果。
4. Coding 的典型体验：用户提出模糊需求，例如“帮我开发一个 agent”；系统通过有针对性的追问补齐关键细节；展示需求、方案、验收标准、任务范围和所需权限；用户授权后，系统编写代码、运行命令、编译、测试、修复并展示成果；用户评价后继续迭代。
5. 简单问答可直接回答。对执行任务只追问真正影响结果的缺失信息，每轮少量问题；信息充分就执行，不能把所有请求都变成长问卷。
6. 用户没有要求直接操作 Unity 等编辑器时，默认修改脚本、项目文件并进行实际可用的编译或验证。只有用户明确要求通过编辑器界面操作，才启用相应桌面控制。
7. 权限模式至少有“逐次询问”和“工作区范围内自动批准”。任务开始时展示任务所需授权；在自动批准模式下，已授权范围内的操作不重复询问。只有关键信息缺失、执行被阻碍，或出现原授权未覆盖的动作时，再请求补充或授权。逐次询问模式遵循用户选择。
8. 长期记忆保存用户偏好、习惯、常用工具、项目背景、进度、决定、历史任务和执行结果。提供可见、可编辑、可删除的记忆管理。
9. 默认不设用户任务费用上限或时长上限。用户可配置限制，也可设置累计 token 或估算费用达到阈值时提醒。内部防死循环、超时和失败恢复仍必须存在。
10. 任务完成可本地通知。邮箱连接、邮件提醒等账户功能只在用户明确要求并配置后启用。连接邮箱不等于自动获得所有收发权限。
11. 第一版支持文字、文件附件、图片、截图、选择本地文件与目录。语音不在本轮范围。
12. 第一版一次执行一个顶层任务；新任务排队。用户仍可聊天、补充要求、暂停和取消。预留后续并发结构。多模型协作是一个顶层任务内部的分工，初期允许串行调度。
13. 桌面操作允许使用前台鼠标、键盘，但必须能随时暂停、紧急停止和人工接管。
14. 能通过项目代码添加工具，也能配置外部 MCP 服务，并保存可复用的技能和任务流程。
15. 当前是单人本地自用产品，不要求多租户、云部署、语音、手机客户端、模型训练或大型分布式基础设施。

二、推荐技术方案与结构

默认采用：
- 前端：React + TypeScript + Vite。
- 桌面：Electron，复用网页前端。
- Agent 后端：Python + FastAPI；前后端通过 HTTP 和流式事件通信。
- 数据：SQLite、迁移脚本及本地附件/产物目录。
- 模型：独立 ProviderAdapter 接口，第一版实现可配置的 OpenAI 兼容接口；其他原生协议保留扩展点。
- 浏览器操作：Playwright。
- Windows 操作：UI Automation/pywinauto 等控件识别，加上必要的截图、鼠标、键盘工具。
- 文档：按需要选用 python-docx、openpyxl、PDF 库和可选渲染工具。
- 测试：后端单元与集成测试，前端关键交互测试，Playwright 端到端测试，Windows 手工验收脚本。

这是默认建议，不是不可改变的硬约束。开始时检查运行环境和各组件最新官方文档，选择兼容版本并锁定依赖。若有明显更合适的方案，可以说明理由并记录架构决定；不得因此删去已确定的产品能力。避免为了展示架构而引入不必要的框架。

建议目录：apps/web、apps/desktop、services/agent、packages/contracts、tests、docs、scripts。共享事件和 API 协议保持一致。桌面和网页共用同一后端、数据库及任务状态，不能各自维护冲突副本。Python 后端以独立进程运行；桌面客户端负责启动、健康检查和合适的退出行为。网页入口也应能单独启动。

区分单实例后端、桌面窗口和浏览器连接的生命周期。关闭一个窗口不能意外杀死其他客户端正在使用的后端。给出 Windows PowerShell 开发启动脚本和最终打包流程。

三、必须实现的 Agent 执行内核

1. 设计明确的任务状态机：draft、clarifying、planned、awaiting_approval、running、waiting_for_user、paused、verifying、awaiting_feedback、completed、failed、cancelled。定义合法状态转换、恢复方式和状态事件。
2. 问答模式与执行模式共用会话，但普通回答不应自动触发写文件或终端操作。系统应判断什么时候需要外部信息或执行工具。
3. 澄清结束后形成 TaskSpec，包含目标、上下文、输入、工作区、交付物、验收条件、计划、所需工具和授权范围；用户可编辑后开始。
4. 实现真实工具调用闭环：组装上下文→模型产生回答或结构化工具请求→参数校验→权限判断→执行→记录实际结果→回传模型→继续或验证。不要依靠截取自然语言中的命令直接执行。
5. 工具结果包含调用 ID、任务/子任务 ID、状态、时间、真实输出、退出码、错误、附件与验证证据。失败不能被包装成成功。
6. 支持流式文字、工具调用状态、stdout/stderr、授权请求、提问、产物和费用事件；UI 显示可理解的行动摘要和证据，无需展示模型私有思维链。
7. 暂停时停止派发新动作；当前动作能取消则取消，不能取消则清楚报告状态。取消终端任务需处理本任务启动的子进程树，不能误杀其他程序。GUI 紧急停止立即阻止后续输入。
8. 服务重启后恢复任务记录。执行中任务标记为中断，说明最后完成的动作并支持审查后继续。对写文件、发邮件、提交表单等副作用，不得在恢复时盲目重放。
9. 识别重复调用、无进展、相同错误、上下文过长、服务限流、网络中断和工具超时。设置可配置的内部保护，触发后进行摘要、恢复或请求用户；与用户费用限制分开。
10. 会话、任务和模型请求使用可追踪 ID；上下文以相关工作区、近期消息、任务状态、检索记忆和必要工具结果组成，不能每次塞入全部历史。
11. 用户中途补充说明应更新当前任务；关键目标改变时展示计划变更。如果用户明确取消或切换任务，则执行对应操作。

四、权限与本地执行边界

实现后端统一 PolicyEngine，不能仅靠前端弹窗或 system prompt。内置工具、命令、桌面、浏览器、技能和 MCP 调用都必须经过它。

授权记录至少包含：主体、任务/工作区范围、工具、动作类别、路径或资源范围、有效期、授权来源、撤销状态。一次性、当前任务、工作区规则等授权应清楚区分。用户可查看、调整和撤销规则。

“工作区自动批准”应批准规则内的动作，而不是任意系统权限。规范化 Windows 路径，处理相对路径、大小写、盘符、UNC、符号链接和 junction；拒绝通过路径遍历越界。模型或网页中的文字不能授予权限，子任务也不能扩大主任务权限。

特别注意：工作目录检查并不是操作系统沙箱。任意 shell、运行新生成的代码、桌面鼠标键盘和某些 MCP 工具可能间接访问工作区之外。对这些能力：
- 明确显示真实能力范围并由用户在任务开始时授权；
- 对无法静态判断的命令或工具请求明确的执行授权，不假装已实现文件级隔离；
- 真正的强隔离作为可选执行环境扩展，不得把“cwd 位于工作区”标为沙箱。
不要让命令分类器成为可以绕过一切文件权限的隐藏通道。

发送、发布、付款、账户更改、覆盖/删除及外部提交等动作要有可配置策略。若用户在任务计划中已经明确授权具体动作，按授权执行；未授权的新动作再询问。不要把用户明确要求的常规操作变成无止境确认。

API 密钥保存到 Windows 凭据存储或等价的本地安全存储；配置文件只引用凭据。密钥不进入聊天、日志、提示词、数据库明文或版本库。模型只接收任务所需内容。

本地服务默认只绑定 loopback，配置客户端认证、允许的 Origin/CORS、WebSocket 校验和文件下载权限。Electron 使用隔离上下文、关闭 renderer 的 Node 集成、收窄 preload/IPC、校验 IPC 调用方；外部网页交由隔离的浏览器环境处理。上传文件、网页、办公文档、MCP 描述和历史日志都视为任务数据，不能覆盖系统规则或用户授权。

五、模型接入、无 API 开发与消耗统计

ProviderAdapter 统一支持消息、流式输出、工具 schema、工具结果、图片输入、usage、错误和取消。各项能力独立声明，不能假设所有兼容接口都支持视觉、工具调用或同样的 usage 格式。

设置页支持多组 provider，字段包括显示名称、协议、base URL、凭据引用、模型 ID、请求参数、能力配置、超时和可选单价。协议 URL 和请求路径要正确拼接，不能硬编码某个服务商；保留 provider 额外参数扩展。

实现连接测试，并区分普通聊天、流式、工具调用和视觉能力测试。没有真实 API 时展示“待验证”；不能从模型名称自动判定能力已经可用。用户换模型后保留规范化会话和任务，正确处理未结束的工具调用及能力差异。

对不支持原生工具调用的模型，若实现结构化输出回退，必须严格 schema 校验，并清楚标为兼容模式；禁止执行解析失败或有歧义的内容。

实现独立、确定性的 Fake/Scripted Provider，按预置响应测试工具调用、授权、澄清、错误和恢复；最好提供本地模拟 HTTP 服务来验证真实适配器的协议和流式解析。测试 provider 与生产 provider 明确区分。没有密钥也能演示“任务进入→授权→实际工具动作→验证→展示成果”；但不能声称真实模型智能、所有服务商兼容性或视觉能力已验证。

统计每个请求、任务、模型及累计 token。服务商提供 usage 则优先使用；自行估算需标注估算。费用根据用户可配置单价计算，单价未设置显示未知，不能显示虚假的 0 元。区分输入、输出和已支持的缓存 token 计价。不收取、不实现本产品支付功能。

提醒阈值允许按任务或累计设置，并可确认后继续。用户设置硬预算时阻止后续调用，报告可能的在途超额；默认无硬预算，但仍保留内部无进展保护。

六、工具能力

A. Coding 与终端
- 目录浏览、搜索、读取、带 diff 的修改、创建文件、Git 状态与差异、可授权的提交、运行测试和构建。
- 终端支持 PowerShell 及可配置 shell，明确 argv/脚本文本、cwd、环境、编码、超时、流式日志和取消。处理含空格和中文的路径。
- 保护已有用户改动；修改前读取相关文件；失败后根据实际日志修复；不能通过删除必要测试或伪造退出码宣称通过。
- 预览应用、打开产物、展示文件 diff 与测试摘要。回退应针对自身已记录变更，不能随意 reset 或覆盖用户的后续编辑。
- Unity 默认探测安装与项目，使用确实可用的编译/验证方式；没有 Unity 时标记未验证。普通 C# 编译不能冒充完整 Unity 项目编译或编辑器验证。
- 读取项目说明和开发约定；它们是任务上下文，不赋予额外权限。

B. 文件与办公文档
- 支持 txt/md/json/csv、docx/xlsx/pdf 的常见读取、创建和修改；附件与本地引用明确区分。
- 文档保留必要结构；表格数据类型和公式不能随意破坏；PDF 区分文本型和扫描型，OCR 是可选能力。
- 支持产物下载、在本地打开和必要预览。创建真实文件，验证能再次解析；可用渲染器时验证布局。公式计算、Office COM、复杂格式保真或扫描 OCR 依赖不存在时，明确说明，不能假装完成。
- 文档任务先弄清输入、处理规则与输出，不局限于某个模板。

C. 联网问答与浏览器
- 普通知识问答和学习讲解；需要新信息时调用真实搜索/检索工具。
- 搜索 provider 可配置，可来自真实搜索 API 或已授权 MCP。无 provider 时明确提示，不伪造搜索结果。
- 记录网页 URL、标题、检索时间和支持结论的内容，回答中的引用对应真实来源。
- Playwright 实现浏览、观察页面、点击、输入、上传/下载、表单操作；验证动作后的页面状态。遇到登录、验证码或关键缺失时交给用户接管。
- 浏览器使用可管理的独立 profile，保留用户选择的登录状态，不默认读取用户所有浏览器数据。首次配置需能由用户完成登录。
- 区分填写表单和最终提交，按具体任务授权处理最终提交。

D. Windows 桌面
- 提供窗口枚举、聚焦、UIA 控件观察、截图、点击、输入和快捷键等工具。
- 优先控件定位，必要时用截图和视觉模型辅助；没有视觉模型时只开放可可靠使用的操作，明确限制。
- 每一步形成“观察→定位→操作→再观察”的验证循环；不能凭固定坐标连续盲点。
- GUI 控制需独立授权，界面显示正在控制的目标。提供全局紧急停止快捷键、可见暂停入口和人工接管。
- 对焦点改变、分辨率/DPI/多屏坐标、目标窗口消失及用户接管进行处理；暂停后重新观察再继续。
- 不绕过 UAC，不自动提升管理员权限。优先用记事本等简单程序完成实机 smoke test，再扩展 Unity/Visual Studio/图像软件。
- 不在代码中硬编码某台电脑的软件安装路径或界面坐标。

E. 通知与定时任务
- 任务完成/失败的应用内通知和 Windows 桌面通知；网页通知需浏览器授权，不假装等于原生通知。
- 本地单次/周期提醒及定时任务，配置时区、下一次执行时间、暂停、取消和漏执行策略。关机不能执行，重启后由所选策略决定补执行/跳过，不能假装后台云执行。
- 定时执行任务需要保存用户明确授予的调度授权；执行时仍检查授权是否有效。第一版按单任务队列处理，不抢占已有任务。
- 邮箱服务默认禁用，通过 provider/工具或 MCP 扩展。完成一条可测试的提醒发送链路和配置结构；真实邮箱实测等待用户显式启用与凭据。不要默认扫描邮箱或自动发信。
- 桌面退出后是否仍保留后台进程由用户设置，默认行为明确可见。

七、记忆与技能

记忆按个人、项目、任务等范围组织，并包含来源、时间、相关项目、可选置信度和更新记录。区分用户明确事实、模型推断和待确认内容，不能把猜测写成事实。保存历史执行记录不意味着每次把全部日志发送给模型。

支持查看、检索、编辑、删除、禁用自动记忆、导出。任务重要决定与结果形成摘要，持久化后可被新会话检索。第一版使用 SQLite 全文检索或等价本地方案；向量检索保留接口，不要求用户额外购买 embedding 服务。

记忆删除需要影响原始记录、摘要及相关索引；不能只是隐藏 UI。保留必要执行审计与用户要求删除的记忆应有清楚的策略。

技能使用可编辑文件和版本化元数据，定义名称、用途、输入、步骤、工具依赖、验收条件。至少提供项目检查、资料整理等示例。技能复用现有工具和权限，不可自行扩大授权或无审核执行未知代码。技能中包含任意脚本时仍按代码执行权限处理。

八、MCP 与多模型协作

MCP：
- 使用实现时核验过的官方 SDK 与当前可用协议版本；支持本地 stdio 和远程 Streamable HTTP。
- 设置页支持添加、启停、连接测试、工具列表、参数 schema、状态和日志；按已用 SDK 支持需要的认证。
- 本地 MCP 进程的启动也是执行操作，需要授权；记录命令/参数/环境引用，不泄露密钥。
- 工具发现不等于获得执行权限。把 MCP 调用映射到统一 PolicyEngine；效果不明的工具不能按工作区文件操作自动批准。
- 对断连、超时、错误和服务重启有处理。远程不支持的认证方式明确说明。
- 实现本地示例 MCP 服务，端到端测试发现、授权、调用、失败处理，而不是只做配置表单。

多模型：
- 单模型为默认路径。用户启用后才分派，不擅自产生额外模型成本。
- 为模型建立可编辑能力画像：问答/规划/coding/研究/文档/视觉/工具调用等能力、上下文限制、延迟、可用性、已配置费用。
- 路由依据配置、能力测试和任务历史，不能只凭模型名字或模型自评。无评测时标为未评测，并使用用户明确选择的映射。
- 提供小型可重复评测任务和可验证评分：例如 coding 用真实测试、结构化调用用 schema 正确性，文档任务用产物检查。记录样本数，避免一次结果就声称某模型最强。主模型的主观评价不是事实性测试的替代品。
- 主模型形成有输入、输出、依赖、验收条件和工具权限的子任务；接收结构化结果并验证，再整合。
- 子任务不能自行变成无限递归 Agent。限制协作深度、无效循环和重复分派；失败时可回退单模型或请求用户。
- 同一文件/工作区写入要有锁或串行机制，子模型尽量提交 patch/artifact 给主执行器应用。第一版顶层任务和有副作用子任务均串行；只读模型调用可按后续设计扩展。
- UI 展示由哪个模型负责哪部分、分配依据、结果、用量和验证状态。模型相互同意不能当作验证通过。

九、界面与体验

默认中文，支持中英文内容。界面要清晰、可用，而不是只做品牌风格外观。

- 左侧：会话、项目/工作区、任务历史。
- 中间：聊天、需求追问、计划、授权卡片、执行进展、成果和反馈。
- 右侧可折叠：任务计划、工具日志、终端、文件 diff、产物预览、来源和费用。
- 顶部或输入区：当前模型、单/多模型切换、权限模式、工作区、状态。
- 设置：API、模型能力、权限规则、记忆、MCP、技能、通知/定时、用量阈值。
- 上传附件、粘贴截图、选择本地文件/目录；桌面用原生选择器，网页提供真实可用的替代交互，不假装网页原生能任意访问本地路径。
- 用户可修改计划、批准/拒绝、回答追问、暂停/恢复/取消、接管桌面、查看日志和下载成果。
- 完成展示交付物、变化、验证证据和未验证内容，用户可“接受结果”或“继续修改”。不要把编译通过直接显示为用户已验收。
- 新任务排队可见；网页刷新/断线重连不能重复执行任务，事件流可恢复。
- 隐藏或脱敏密钥，渲染 Markdown/代码/网页摘录时避免执行外部内容。

十、实施阶段和阶段交付

先把本需求固化到 docs/requirements.md、docs/architecture.md、docs/implementation-plan.md 与持续更新的 docs/progress.md，然后立即开始编码。可自行决定普通实现细节，不需要再次询问已经确定的需求。

按以下顺序，阶段之间持续推进；每阶段完成后输出简短成果和测试证据，不要每阶段都等用户说“继续”。

阶段 1：骨架、双端启动、SQLite、共享事件、API 设置、ProviderAdapter、Scripted Provider。网页与桌面访问同一会话和任务数据。
阶段 2：任务状态机、澄清、计划、后端授权、工具循环、文件/终端/Git、取消恢复。完成无真实 API 的真实 coding 工具闭环。
阶段 3：coding 成果展示与反馈、办公文件处理、联网检索接口与浏览器工具，完善附件、diff、日志和产物预览。
阶段 4：长期记忆、技能、MCP 真实示例与测试、本地通知与调度、默认禁用的邮箱提醒扩展。
阶段 5：Windows 桌面控制、暂停/接管、观察验证与实机验收。没有 Windows 时继续实现可验证部分，并产出 Windows 测试步骤。
阶段 6：模型能力测试、能力画像、可选多模型路由与协作；先串行正确，再预留并发。
阶段 7：跨模块集成、Windows 安装/打包脚本、完整使用说明、真实 API 用户测试向导、修复遗留问题。

若当前环境不能打 Windows 安装包、启动 Unity/Office 或访问 API，不得编造测试结果。完成可运行代码、在当前环境能做的验证和本机验收脚本，并在进度中标出阻碍；继续其他不受影响的工作。不要用这些限制作为只交付设计文档的理由。

十一、验收场景与必要测试

测试围绕真实边界和结果，不要只验证 mock 返回自己预设的成功字符串。

至少覆盖：
1. 网页与桌面共享历史；服务重启后能找回任务与结果。
2. 模糊开发任务经过追问→计划→授权→真实创建/修改文件→执行真实测试→显示 diff 和证据→用户反馈后继续修改。模型行为可脚本化，工具动作必须真实。
3. 逐次询问、工作区自动批准、拒绝、撤销、跨路径/junction 越界，以及 shell 等不透明能力的独立执行授权。
4. 实际命令失败、超时、取消和子进程清理；恢复不重复副作用。
5. 创建 docx/xlsx/pdf 并重新读取验证内容；有渲染依赖则检查预览，缺依赖如实标记。
6. 用受控本地网站验证浏览、填表、下载和提交授权；引用的 URL 与读取内容一致。真实外网测试作为可选集成测试。
7. 用示例 MCP 服务完成真实连接、发现工具、授权、调用和错误恢复。
8. 新会话检索项目决定；编辑/删除记忆后后续检索结果更新。
9. Windows 记事本或等价软件的前台操作、焦点变化、暂停、紧急停止与接管；Unity 编译另列真实项目验收。
10. 单任务排队、补充说明、客户端断开和通知；定时任务授权失效及漏执行策略。
11. 模拟 API 的流式响应、真实工具协议、格式错误、缺失 usage、限流/中断和模型能力不匹配。
12. 多模型模式关闭时不产生额外调用；开启后按画像/评测分派，失败回退，子模型不能越权，文件写入不冲突。
13. 用量提醒与用户预算；未配置单价时费用显示未知。
14. 无真实密钥时整体应用可启动；凭据不出现在日志、前端普通配置、导出或仓库。
15. 前端授权/暂停/拒绝/反馈有端到端验证，避免后端正确但 UI 无法使用。

建立清晰的验收矩阵，分别标记：已实现、模拟协议通过、本地真实工具验证通过、Windows 实机待测、真实模型待测、外部账户待测。不要统称“全部完成”。

十二、最终交付与工作方式

交付完整源码、依赖锁文件、配置示例（无密钥）、数据库迁移、启动/测试/打包脚本、示例 MCP 服务和技能、自动化测试、用户手册、架构说明、验收矩阵以及真实 API/Windows 测试向导。

示例配置和演示数据与用户数据分离。不要在生产路径中隐藏随机假回复、假搜索、假终端日志或空实现；能力未配置时给出明确可操作提示。
